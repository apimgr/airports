# External Integrations

The Airports server is designed to run with **no required external dependencies** beyond a TCP socket. Every integration below is optional and gracefully degrades if unavailable.

## GeoIP — ip-location-db

| Item | Value |
|------|-------|
| Provider | [ip-location-db](https://github.com/sapics/ip-location-db) (CDN-distributed via jsDelivr) |
| Files | `asn.mmdb`, `country.mmdb`, `city.mmdb`, `whois.mmdb` |
| License | CC0 / PDDL (no API key, no account required) |
| Format | MaxMind MMDB binary |
| Update cadence | Daily |
| Storage | `{data_dir}/security/geoip/` (~80 MB total) |
| Required? | No — server runs without GeoIP; home page falls back to a generic view |

Outbound URL pattern: `https://cdn.jsdelivr.net/npm/@ip-location-db/...`.

Used for:

- Caller location detection on the home page (to surface nearby airports).
- ASN attribution in abuse-investigation logs.

GeoIP lookup results for callers are **never logged or stored** — they are computed per-request and discarded.

### Disabling GeoIP

```yaml
# server.yml
geoip:
  enabled: false
```

When disabled, the home page shows a generic list of major hubs instead of nearby airports.

## Airport Dataset — embedded

The 35,000+ airport records are baked into the binary at compile time from the [OurAirports](https://ourairports.com/data/) public dataset. There is **no runtime fetch** of airport data. Updating the dataset requires rebuilding the binary and shipping a new release.

## TLS Certificates — Let's Encrypt (optional)

| Item | Value |
|------|-------|
| Provider | Let's Encrypt via ACME v2 |
| Challenge types | HTTP-01 (default), DNS-01 |
| Endpoint | `https://acme-v02.api.letsencrypt.org/directory` |
| Storage | `{config_dir}/ssl/acme/` |
| Renewal | Automatic (every 12 hr check, renew at < 30 days remaining) |
| Required? | No — operator may supply their own cert/key, or use HTTP-only |

Enable in `server.yml`:

```yaml
tls:
  enabled: true
  acme:
    enabled: true
    email: ops@example.com
    domains: [airports.example.com]
    challenge: http-01
```

## Tor — Hidden Service (optional, default on in container)

The binary owns Tor entirely — it installs `torrc`, manages hidden-service keys, and starts/stops the Tor process.

| Item | Value |
|------|-------|
| Binary | `tor` (Alpine package; bundled in Docker image) |
| Config | `{config_dir}/tor/torrc` (generated by server binary) |
| Keys | `{data_dir}/tor/hs_ed25519_*` (perms 0600) |
| Hostname | `{data_dir}/tor/hostname` (the `.onion` address) |
| Required? | No — `tor.enabled: false` disables it entirely |

If Tor fails to start the server continues without it; the warning is logged.

## SMTP — Outbound Email (optional)

Used only for admin notifications (e.g., backup failure alerts). Auto-detected when SMTP config is present.

```yaml
smtp:
  host: smtp.example.com
  port: 587
  username: user@example.com
  password: "<env or vault>"
  from:     "airports@example.com"
  tls: starttls
```

This project has no user accounts, so transactional email (signup, password reset) does not exist.

## Self-Update — GitHub Releases

When `airports --update` is invoked the binary contacts `https://api.github.com/repos/apimgr/airports/releases/latest`, downloads the matching `{os}/{arch}` tarball, verifies the SHA-256 checksum from the release assets, and replaces itself in place via atomic rename.

Disabled inside Docker — the user is instructed to `docker pull` instead.

## Reverse Proxy — Auto-detected

The server auto-detects when it is behind a reverse proxy via `X-Forwarded-Proto`, `X-Forwarded-Host`, and `X-Forwarded-For` headers and adapts:

- `DOMAIN` (no manual `server.yml` entry needed)
- Scheme (`http` vs `https`)
- Remote IP (uses the leftmost public address from `X-Forwarded-For`)

Works out of the box with nginx, Caddy, Traefik, HAProxy, and Cloudflare.

## Container Runtime — Docker / Podman

The image runs unprivileged. Two volumes mount the entire runtime state:

```yaml
volumes:
  - ./volumes/config:/config:z
  - ./volumes/data:/data:z
```

Compatible with Docker, Podman, containerd, and any OCI-compliant runtime.

## What the Server Does NOT Integrate With

- **No OAuth / OIDC / SAML** — no user accounts exist.
- **No external database server required** — embedded SQLite for operational state.
- **No external cache** — in-process LRU.
- **No external scheduler** — built-in cron (do not deploy host cron / systemd timers).
- **No telemetry / analytics / phone-home** — outbound HTTPS only for GeoIP refresh, ACME (if enabled), and self-update (when explicitly invoked).
